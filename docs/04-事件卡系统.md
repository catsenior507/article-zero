# 04 · 事件卡系统

## 1. 三类卡

| 类型 | 作用 | 长度 | 出现方式 | 占比 |
|---|---|---|---|---|
| **日常** | 让组织像"有人住"；低风险地塑造意识形态与人物 | 1 段简报 + 3 选项 | 权重随机 | ~40% |
| **流程** | 制度的齿轮：分级、配额、审计、谈判、掩盖。正确答案往往令人不适 | 1 段简报 + 3 选项 + 延迟后果 | 权重随机，按部门解锁 | ~35% |
| **关键** | K 链节点、人物弧、制度转折、元事件。改变本局形状 | 1 段简报 + 2–3 选项 | **排期触发**，不随机 | ~25% |

> 关键卡不进随机池。它们由 `turn`、`clock`、`flag` 触发。这保证"该来的一定会来"，玩家不会因为运气错过主线。

## 2. 卡牌模板

写卡时按这个顺序填，不要跳：

```markdown
### 编号 标题
`类型` `时期` `牌堆` `权重`

**简报**：两到三句。用公文、口述或日志的口吻。必须包含一个具体的、可被误读的细节。

**选项**
- **A｜动作**：效果｜效果｜轴
- **B｜动作**：效果｜效果｜轴
- **C｜动作**（需 部门 ≥N）：效果｜效果｜轴

**暗线**：在什么条件下、多少回合后，触发哪张后续卡。
```

### 简报的三条硬规则

1. **必须有一句"不对劲"。** 哪怕是日常卡。
2. **不写情绪。** 不写"你感到不安"，写"记录显示"。
3. **必须有一个可以被忽略的细节。** 这个细节在 10 回合后变成关键。

### 选项的三条硬规则

1. 每个选项必须是**一个具体动作 + 一个责任人/部门**。
2. 至少一个选项是**制度解法**，至少一个是**人的解法**，两者不能同时选。
3. 代价不写在选项标题里。玩家要读效果才知道。

## 3. 字段 schema（TypeScript）

```ts
type CardKind = 'daily' | 'procedure' | 'key';
type Era = 'early' | 'mid' | 'late' | 'any';
type Axis = 'C' | 'L' | 'K' | 'V' | 'P';   // 正极：集权/专制/冷酷/守秘/超验
type ResourceKey =
  | 'funding' | 'staff' | 'morale' | 'capacity' | 'assets'
  | 'veil' | 'contamination' | 'authority' | 'consensus' | 'awakening';

interface Card {
  id: string;                 // "D-01" / "P-04" / "K-08"
  kind: CardKind;
  era: Era;
  title: string;
  deck: string[];             // 'site' | 'personnel' | 'anomaly' | 'politics' | 'veil' | 'meta'
  weight: number;             // 随机池权重，关键卡为 0
  cooldown: number;           // 再次出现的冷却回合
  once?: boolean;             // 一局一次
  requires?: Requirement;     // 出现条件
  brief: string;              // 简报正文
  options: Option[];          // 2–3 个
  followUp?: FollowUp[];      // 暗线（延迟触发的卡）
  tags?: string[];            // 'xk_omen' | 'ledger' | 'named_npc'
}

interface Requirement {
  turnMin?: number; turnMax?: number;
  dept?: Record<string, number>;          // 部门最低等级
  flags?: string[]; notFlags?: string[];
  resource?: Record<string, [number, number]>;  // [min, max]
  kChain?: string; stage?: number;
}

interface Option {
  id: 'A' | 'B' | 'C' | 'D';
  label: string;                          // 动作，不含代价
  cost?: Partial<Record<ResourceKey, number>>;
  gain?: Partial<Record<ResourceKey, number>>;
  axis?: Partial<Record<Axis, number>>;   // 正负均可
  requires?: Requirement;                 // 选项级门槛（部门/资源）
  risk?: number;                          // 0–1，隐藏，影响 delay 卡的走向
  result: string;                         // 结算文本，1–2 句
  ledger?: number;                        // 账本增量（冷酷代价）
  flags?: string[];
  clock?: Record<string, number>;         // 对 K 链时钟的即时影响
  schedule?: Scheduled[];
}

interface Scheduled {
  inTurns: number;
  card?: string;                          // 触发哪张卡
  effects?: Partial<Record<ResourceKey, number>>;
  text: string;                           // 排期文本，会写进档案
}

interface FollowUp {
  ifFlag?: string; ifNoFlag?: string;
  inTurns: number;
  card: string;
}
```

### 为什么效果要分 `cost` / `gain`

结算界面分两栏：**支出**与**获得**。玩家看到的是"你付出了什么、拿到了什么"，而不是一个净值。这是本作的气质：基金会永远把代价单列。

## 4. 数值口径

| 项 | 常规范围 | 关键卡上限 | 说明 |
|---|---|---|---|
| 经费 | ±2 ~ ±15 | ±20 | 月度结余 ±10 以内算健康 |
| 编制 | ±3 ~ ±20 | ±30 | 100 为满编 |
| 士气 | ±3 ~ ±12 | ±20 | 0–100，编制的子属性 |
| 容量 | ±2 ~ ±10 | ±12 | 40 为初始上限 |
| 资产 | ±1 | ±2 | 0–12 |
| 帷幕 | ±2 ~ ±8 | ±12 | 0–100 |
| 污染 | +1 ~ +8 | +12 | **只增不减**，除"遗忘" |
| 权威 | ±3 ~ ±10 | ±20 | 0–100 |
| 共识 | ±3 ~ ±10 | ±15 | 0–100 |
| 轴 | ±2 ~ ±5 | ±10 | 单局单轴净位移建议 ≤120 |
| 账本 | 0 ~ 3 | 5 | 只记数，不结算 |

**平衡红线**：单张卡的净值（gain − cost 折算）不超过 12 点当量；否则它会变成"必选卡"，破坏抉择。

## 5. 配重与排期

### 抽卡

```
每回合抽 3 张：
  weight = base_weight
         × era_multiplier      // 前期 1.0 / 中期 1.2 / 后期 1.4
         × contamination_mul   // 污染 >40 时，异常类 ×1.5
         × (1 + 0.1 × 未完成K链数)
```

- 同名牌冷却 6 回合（关键卡除外）。
- 若抽到的 3 张全部来自同一牌堆，强制重抽 1 张。
- 污染 ≥70 时，有 15% 概率插入一张**假卡**（无正确选项，选什么都是代价）。

### 排期触发

| 触发源 | 例子 |
|---|---|
| 回合数 | `turn == 27` → K-11 你为谁守夜 |
| K 链时钟 | `clock <= 55` → K-03 多出来的一行 |
| 旗标 | `flag:ledger_open` → K-12 继承审查 |
| 账本 | `ledger >= 6` → 「点名」事件 |
| 元状态 | `awakening >= 80` → K-14 方舟 |

## 6. 文本风格指南

### 三种声音，轮换使用

| 声音 | 特征 | 例 |
|---|---|---|
| **公文** | 被动语态、编号、免责 | "经评估，该方案在现行条例下不构成违规。" |
| **口述** | 短句、省略主语、有口头禅 | "别数第二遍。数第二遍它就知道了。" |
| **日志** | 时间戳、断句、突然中断 | "03:14。它又在门外了。这次它敲门。" |

### 好 / 坏对照

| 坏 | 好 |
|---|---|
| "你感到一阵寒意。" | "室温记录显示 14°C。空调没有启动。" |
| "这个选择很艰难。" | "两个方案都已在文件上盖章。你只需要选一个归档。" |
| "异常项目非常危险。" | "项目等级：Keter。附注：它上周申请了一份报纸。" |
| "你的决定将影响很多人。" | "本决定涉及 412 名在编人员。名单见附件。" |

### 中文语感

- 少用"你"，多用无主句。基金会的文件不称呼读者。
- 数字用阿拉伯数字，单位用中文（"3 厘米""12 人"）。
- 编号用 `█` 遮蔽：`Site-██`、`O5-7`、`SCP-8███`。
- 不用感叹号。一次例外：某张关键卡的最后一句话。

## 8. 写卡的检查清单

出卡前逐条自查：

- [ ] 简报里有一个 10 回合后会变成伏笔的细节？
- [ ] 三个选项分别代表三种**制度**，而不是三种"态度"？
- [ ] 有没有一个选项是"什么都不做"？如果有，它有没有代价？
- [ ] 代价是否延迟？延迟是否具名？
- [ ] 这张卡放进牌库，会不会让某条 K 链变得无解？
- [ ] 玩家第二次抽到它时，会不会因为局势不同而做不同选择？
- [ ] 去掉所有数值，这段文字还像基金会吗？
