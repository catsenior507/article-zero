## 3. 士气规则

每月结算一次（游戏日 +30）：

```
编制满足率 sr = staff / needStaff
D 级满足率 dr = dclass / needDClass

Δmorale = sr ≥ 1 ? +1 : sr ≥ 0.8 ? −1 : −2
若 dr < 0.7，再 −1
morale 夹在 0–95
```

| 士气 | 状态 | 后果（M14.4 实现） |
|---|---|---|
| ≥ 55 | 正常 | 无 |
| 40–54 | 低落 | 产出 −10%，事件选项变少 |
| < 40 | **低效** | 产出 −25%，K 级响应慢 1 回合 |
| < 25 | 濒临停摆 | 每月有 15% 概率罢工，站点停摆 2 回合 |

设成"每月一次"而不是每天，是为了让玩家看见趋势，而不是被数字抖动骚扰。

## 5. 界面

- **点击顶栏任一资源**（经费 / 编制 / 士气 / 容量 / 污染）打开资源面板；
- 面板有「部门 / 站点」两个页签，按资源类型自动切换；
- 每行：名称、当前值 / 需求、比例条、状态（充足 / 紧张 / 缺员 / 低效）；
- 状态色：缺员红、紧张灰、充足琥珀；
- 资产、帷幕、权威、共识是全局指标，面板显示"不按部门或站点分配"。

组织面板里，"官方设定 / 按职能推定"改成小字括号注脚（`（官方设定）`），因为它只是考据标注，不参与游戏。

## 6. 存档结构

```js
world.org: {
  levels: { pata: 3, ... },
  depts: {
    pata: { staff: 6, dclass: 120, morale: 71 },
    ops:  { staff: 20, dclass: 420, morale: 62 }
  }
}
```

需求线、预算、站点容量是静态定义，放在 `org.js`；只有会变的三个数进存档。
