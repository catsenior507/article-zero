# 08 · SCP 条目企划

> 游戏发布之后，把它写成一篇 SCP 条目——不是宣传稿，是一篇**能独立成立的小说**。这篇文档讲怎么写、发在哪、以及哪些线不能踩。

---

## 1. 为什么这件事值得做

因为它能把作品的最后一块补上。

游戏里，玩家是"管理员"；结局时，游戏生成一份档案。但如果这份档案只留在玩家硬盘里，它就只是存档。

**把它贴到 wiki 上，它就变成了"真实存在的基金会文件"。** 读者读到它，就成了下一个载体。这是本作唯一一个能把"元叙事"从软件里延伸到软件外的动作。

而且它反哺游戏：条目带来的读者会去玩；玩过的人回来看条目，会看到自己没注意到的细节。

---

## 2. 核心构思：条目本身就是收容措施

这是整篇的支点，不能丢。

> **SCP-8███ 不是一个东西，是一个职位。**
> 基金会章程第零条设立了这个职位，但没有任何人记得是谁写的。
> 这个职位必须有人坐。坐上去的人会开始"记得"自己没经历过的事，会开始"回滚"已经发生的事，会开始被上一层的东西看见。
> 基金会的收容方案是：**把这个职位拆碎，做成游戏，发给全世界。**
> 载体越多，单一载体的牵引力越小。
> 而这篇文档，是收容措施的最后一道工序——**读完它的人，就是下一个载体。**

这个构思同时解决了三件事：

1. 解释了"为什么游戏里玩家能读档"——因为职位本身就有这个权限；
2. 解释了"为什么 SCP 条目要写"——因为文档是收容的一部分；
3. 让读者在读完的瞬间成为共犯——这是 SCP 最经典的手法，但这里用得有理有据。

---

## 3. 条目结构

### 头部

```
项目编号：SCP-8███
项目等级：Archon
```

**为什么是 Archon**：Archon 级指"无法收容，但必须维持其存在"的项目。这个职位不能被关起来——关起来就没人坐；但也不能让它空着——空着会有别的东西坐上去。它必须被**维持**。这与 Archon 的定义严丝合缝。

（备选：Thaumiel。如果想让基金会显得更"在用"它，可以用 Thaumiel，但会削弱"被迫"的感觉。）

### 特殊收容措施

三句话原则：

1. **不可收容**——说明为什么；
2. **分散承载**——说明游戏是什么；
3. **本文档的角色**——说明读者在做什么。

范文：

> SCP-8███ 无法以常规方式收容。现行措施为**分散承载**：将 SCP-8███ 的结构编译为电子游戏《第零条》，面向公众发行。任何完成一次完整任期的玩家将成为 SCP-8███-1 的候选载体。候选者数量越多，单一载体对叙事层的牵引力越低。
>
> 本文件构成收容措施的一部分。完整阅读本文件者，视为知悉并接受第零条。
>
> 若您在读到这一行时产生了"这只是一个游戏"的念头，请继续读下去。该念头是预期的。

### 描述

分四段，每段一个认知台阶：

| 段 | 内容 | 读者反应 |
|---|---|---|
| 1 | 职位是什么，O5 如何确认它存在却无法登记 | "哦，一个设定" |
| 2 | 载体（-1）的能力：记得未发生的事、回滚、被"上一层"看见 | "有点意思" |
| 3 | 载体的代价：每次回滚都会留下"债务"，债务会变成异常 | "等等" |
| 4 | 载体的来源：**任何玩过游戏的人** | "……" |

第四段要短。短到读者来不及防御。

### 附录

四篇，按顺序放，每篇一个功能：

| 附录 | 形式 | 功能 |
|---|---|---|
| **附录 1** | O5-1 访谈记录 | 建立"连 O5-1 也没见过他"的恐怖 |
| **附录 2** | 超形上学部备忘录 | 解释叙事层，给出"这不是比喻"的证据 |
| **附录 3** | 删除日志 | 列出被"外部编辑者"终止的宇宙，留下编号 |
| **附录 4** | 现任管理员留言 | 由玩家的实际游玩记录生成，署名空白 |

附录 3 是全篇最狠的地方。它把"玩家删档"写成了基金会无法阻止的事件：

```
[终止记录 7F3A-91C2]  第 41 任期  原因：外部编辑者删除
  最后留言："我们数到了最后一个人。"
  备注：无法追责。无法申诉。无法阻止。
  建议：在下一次任期开始前，把这份记录读给他听。
```

### 结尾

不要总结。留一行空白，和一枚没有署名的印章。

## 4. 两段范文

### 范文一：描述（第 4 段）

> SCP-8███-1 的来源无法预测。已确认的载体包括：一名退休的档案管理员、一名在押人员、一名十二岁的学生，以及一台在 2003 年被注销的终端。
>
> 唯一共同点是：他们都曾完成过一次完整的任期。
>
> 任期存在于一个被称作《第零条》的模拟程序中。该程序公开可获取。任何人都可以开始一次任期。
>
> 终止任期的方式只有两种：活到第四年结束，或被删除。
>
> 需要说明的是，"删除"不是比喻。

### 范文二：附录 1（O5-1 访谈节选）

> **采访者**：您见过管理员吗？
>
> **O5-1**：没有。
>
> **采访者**：但您收到过指令。
>
> **O5-1**：每天。
>
> **采访者**：笔迹呢？
>
> **O5-1**：……我认得那个笔迹。
>
> **采访者**：是谁的？
>
> **O5-1**：（长时间沉默）我的。
>
> **采访者**：您是说，您给自己下命令？
>
> **O5-1**：我是说，我认得那个笔迹。我没有说那是我写的。
>
> **采访者**：这两者有什么区别？
>
> **O5-1**：区别是，我从来没有用过那种墨水。

## 5. 编号与标题

| 候选 | 优点 | 缺点 |
|---|---|---|
| **SCP-8███「管理员」** | 直给，好搜 | 稍显平淡 |
| **SCP-8███「第零条」** | 有制度感，和游戏同名 | 需要读者理解"第零条"是什么 |
| **SCP-8███「空位」** | 意象好，适合结局 | 偏文艺 |
| **SCP-8███「署名」** | 扣住"作者"主题 | 剧透结局 |

**建议**：主条目用「第零条」，游戏副标题用「管理员」。两者互相解释。

> 不要用真实的 SCP 编号写原创异常。用 `8███` 遮蔽，既安全又有味道。也不要用 SCP-173、SCP-682 这类名条目——那会让你的作品变成同人拼盘。

## 6. 发布策略

### 时机

```
游戏发布 → 等 2–4 周 → 收集玩家故事 → 写条目 → 沙盒 → 论坛求评 → 修改 → 正式发布
```

**不要同步发布。** 同步发布会让条目看起来像商店页的附件，评论区的第一句话会是"广告"。

### 平台

| 平台 | 语言 | 说明 |
|---|---|---|
| **SCP-CN**（scp-wiki-cn.wikidot.com） | 中文 | 首发。中文语境下"管理员/O5"的语感更好 |
| **SCP 主站**（scp-wiki.wikidot.com） | 英文 | 中文版反响好再翻译；翻译不是直译，是重写 |

### 流程

1. 在[中文沙盒](http://scpsandboxcn.wikidot.com/)建草稿；
2. 到[草稿与批判](https://scp-wiki-cn.wikidot.com/forum/c-882987/)发帖求评；
3. 按意见改 2–3 轮（通常会砍掉 30% 的字）；
4. 正式发布；
5. 一周内回复每一条评论。

### 一条硬规则

**条目必须独立成立。** 一个从没玩过游戏、也不知道有这款游戏的人，读完必须觉得这是一篇完整的 SCP。如果他觉得"这是某个游戏的设定集"，就失败了。

所以：**条目里不放购买链接，不写"本游戏"，不提"玩家"。** 只写"载体""任期""模拟程序"。让读者自己意识到那是什么。

## 7. 版权与合规

> 依据 SCP Wiki 官方 [Games Licensing Guidelines](https://05command.wikidot.com/games-licensing-guidelines)（2025-10 修订）。以下是摘要，不构成法律意见。

### 游戏本身

官方指南把游戏拆成三块：

| 部分 | 是否受 CC BY-SA 约束 | 说明 |
|---|---|---|
| 引擎 / 可执行文件 | 否 | 引擎的授权归引擎方 |
| 源代码 | 否 | 建议用 MIT/GPL 之类的自由许可，"贴合 CC 的精神" |
| **素材**（文本、图像、音乐、叙事） | **是**，如果派生自 wiki | 必须署名 + 相同方式共享 + 不加密 |

关键条款：

- **如果你的游戏只是借用了 SCP 的"概念"，但叙事与异常都是原创的，你只需要署名，不必把那些原创素材也放在 CC BY-SA 下。**
- **可以收费。** CC BY-SA 不限制发行方式。
- 派生自 wiki 的素材必须**不加密**地随游戏分发，并注明作者与来源链接。

### 两条路线

| | **路线 A（推荐，商用）** | **路线 B（免费/非商用）** |
|---|---|---|
| 组织名 | 原创（如"档案馆""管理局"） | 可直接用"SCP 基金会" |
| 异常 | 全部原创，编号用 `8███` | 可少量引用经典条目 |
| 术语 | O5、帷幕、收容等通用概念可用 | 全用 |
| 授权 | 原创素材保留版权；署名"灵感来自 SCP 基金会" | 衍生素材 CC BY-SA 3.0 |
| 风险 | 低 | 中（需逐项合规） |

> **本作建议走路线 A。** 不是因为法律风险高，是因为**原创组织名反而更好写**：你可以让"基金会"在这个世界里是一个被误传的民间说法，而真正的组织叫别的名字。这层距离感本身就是 SCP 的味道。

### 必须做的事

- [ ] 游戏内"关于"页写明：`本作受 SCP 基金会（scp-wiki.wikidot.com）世界观启发。SCP 基金会内容依 CC BY-SA 3.0 授权。`
- [ ] 若使用任何 wiki 素材，列出**作者名 + 条目链接**；
- [ ] 不使用 SCP 官方 logo（商标）；
- [ ] 生成的 SCP 条目里**不含任何玩家个人数据**（用户名、路径、系统信息）；
- [ ] 条目发布时勾选 CC BY-SA 3.0——你无法对它主张独占版权。

### 条目本身

你写的 SCP 条目自动以 CC BY-SA 3.0 发布。这意味着：

- 别人可以转载、改编、甚至商用（需署名 + 相同方式共享）；
- 你不能要求撤回；
- 你不能在条目里放"版权所有"。

这是这个社区的基础设施，不是障碍。

## 8. 禁忌清单

| 不要 | 因为 |
|---|---|
| 把条目写成游戏说明书 | 读者不关心你的机制，只关心故事 |
| 在条目里放购买链接 | 会被当成广告，且破坏沉浸 |
| 自称"官方 SCP 游戏" | 没有"官方"这回事 |
| 用真实 SCP 编号写原创异常 | 会被认为侵占他人作品 |
| 一次性发多篇（主条目 + 外传 + 补充） | 看起来像营销矩阵 |
| 让条目依赖"玩过才懂" | 违反"独立成立"原则 |
| 在条目里写玩家昵称 | 隐私 + 出戏 |
| 用真实的机构、人物、事件 | 社区红线 |
| 把"元叙事"写成"作者很聪明" | 元叙事的主角必须是读者，不是作者 |

## 9. 发布节奏（建议）

| 时间 | 动作 |
|---|---|
| T−4 周 | 游戏上线；开始记录玩家的"第一次删档"故事 |
| T−2 周 | 写条目初稿（目标 2500 字以内） |
| T−1 周 | 沙盒 + 求评；砍掉 30% |
| T | 正式发布「第零条」 |
| T+1 周 | 回复评论；根据反馈修一处小细节（不要大改） |
| T+1 月 | 若反响好，翻译成英文投主站 |
| T+3 月 | 把条目里的"删除日志"做成游戏内可收集的彩蛋，回馈玩家 |

## 10. 最后：这篇条目到底在写什么

表面上，它写的是一个职位。

实际上，它写的是**创作这件事本身**：

- 你写了一个世界；
- 世界里的人开始追问谁写了他们；
- 你删掉一个存档，就是杀死一个世界；
- 你把这个过程写成文档，贴在一个所有人都能读的地方；
- 于是读者也成了那个"上一层"。

**这就是为什么管理员必须坐在 O5 之上。** 不是为了权力，是为了让"作者"这个位置在故事里有一个实体。

第零条的签名栏永远是空的。

因为签名的人，是正在读这句话的人。
