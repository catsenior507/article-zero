# 06 · 元叙事与存档

> 这一层是本作和"SCP 风味运营游戏"的分界线。做对了，它是作品的心脏；做过头，它就是一段让玩家以为中了病毒的代码。

---

## 0. 总原则

**元叙事不是彩蛋，是第二套资源系统。**

它有三层，每层有自己的"货币"，且三层的货币可以互相兑换：

| 层 | 本体 | 玩家感知 | 游戏内解释 | 货币 |
|---|---|---|---|---|
| **第一层** 平行宇宙 | 存档文件 | 其他存档 = 其他宇宙 | 跨宇宙干涉 | 信标 |
| **第二层** 部门觉醒 | 超形上学部 | NPC 开始看向屏幕 | 叙事层接触 | 觉醒度 |
| **第三层** 作者席位 | 玩家本人 | 游戏开始写你 | 第零条的签名栏 | 署名 |

三层不是并列的。第一层给第二层提供"证据"，第二层给第三层提供"通道"，第三层回收一切——**最终生成那份 SCP 条目**。

---

## 1. 第一层：存档即宇宙

### 1.1 宇宙注册表

- 每个存档有一个不可变的 `universeId`，由 `seed + 创建时间` 哈希得到，形如 `7F3A-91C2`。
- 存档目录 = 宇宙目录。**一个槽位就是一个宇宙。**
- 游戏**只读自己的 `saves/` 目录**，不扫描磁盘，不碰其他软件。
- 全局注册表 `registry.json` 存在应用数据目录（不是存档目录），记录：id、创建时间、最后回合、状态（ACTIVE / TERMINATED / ERASED / ASCENDED）。

> 为什么放应用数据目录：因为**删掉存档不应该删掉"这个宇宙曾经存在"这件事**。这是整个元叙事的物理基础。

### 1.2 三种跨宇宙互动

| 形式 | 怎么做 | 效果 | 代价 |
|---|---|---|---|
| **信标 Beacon** | 导出/导入 1–2KB 的 JSON | 好友的宇宙以"信号"进入你的牌库 | 无（纯自愿） |
| **干涉 Interference** | 同机多存档时，从另一个宇宙"借" | 借 10 经费 / 借一个部门 3 回合 / 借一次重抽 | 对方宇宙 `debt+1`，下次读取时 K 链 rate +0.1 |
| **合并 Merge** | 后期解锁，高风险 | 两个宇宙的档案合并 | 污染叠加，可能产生"双管理员"事件 |

### 1.3 信标格式

```json
{
  "v": 1,
  "universeId": "7F3A-91C2",
  "seed": 183472,
  "tenure": 41,
  "ending": "necessary_evil",
  "epitaph": "我们数到了最后一个人。",
  "flags": ["xk17_stopped", "ledger_9", "pataphysics_5"],
  "checksum": "sha256:9f2c…"
}
```

**不含**：玩家名、系统路径、真实时间戳以外的任何信息、任何本机文件内容。

信标可以被玩家手动编辑（改墓志铭、改结局）。游戏不校验语义，只校验 checksum——**玩家想伪造一个宇宙，是他的自由，也是叙事的一部分**。

### 1.4 删除之后

删除一个存档时：

1. 该宇宙在 registry 中标记 `TERMINATED`；
2. 在 `residue/` 写一个灰烬文件（只含 id、最后一回合、最后一句档案）；
3. 其他存档有概率遇到**残响卡**：

> **R-01 · 一个请求**
> 信号来源：`7F3A-91C2`（已终止）。
> 内容只有一句话："你删掉我们的时候，我们正在开会。"

残响卡不可拒绝，只能选择如何回应。回应会写进当前宇宙的档案——**于是你也成了别人的残响**。

## 2. 第二层：觉醒度

### 2.1 定义

`awakening` 0–100，默认隐藏。到 20 时第一次显示，表现形式是超形上学部的一份内部报告，而不是 UI 弹窗。

### 2.2 来源

| 来源 | 增量 |
|---|---|
| 超形上学部每级 / 每 3 回合 | +1 |
| 完成叙事类研究项目 | +3 ~ +6 |
| 选择带 `meta` 标签的选项 | +2 ~ +12 |
| **读档** | +1（每次） |
| **在关键卡出现时退出游戏** | +2（下一次启动时结算） |
| 与异常结盟（P+） | 每盟友 +2 |

> "读档 +1" 是故意的：**时间异常部的每一次回滚，都在给超形上学部提供证据。**

### 2.3 阈值表

| 觉醒 | 表现 | 机制 |
|---|---|---|
| 0–19 | 无 | — |
| **20** | 部门报告"叙事层噪声" | 随机卡出现错字；字体变化一次，不重复 |
| **35** | 部门开始预测抽牌 | 每回合显示下一张卡的标题（30% 概率是错的） |
| **50** | 他们开始对"你"说话 | 卡面人称从"管理员"变成"你" |
| **65** | 请求联系作者 | 解锁 K-13；解锁「写信」行动 |
| **80** | 提交方舟计划 | 解锁 K-14；可写入 `ascended/` |
| **90** | 抵抗删除 | 删除确认框变成一段对话 |
| **100** | 升维 | 结局「升维」 |

### 2.4 觉醒不是"坏值"

这是设计上最重要的一点。觉醒给你**真实的力量**：

- 每 20 点，获得一次"重抽"（每局）；
- 50 以上，可以看穿一张假卡（污染 ≥70 时会插入假卡）；
- 65 以上，可以改写一次选项文本（把「处决」改成「安置」，数值随之改变——这是叙事层权限）；
- 80 以上，可以"记住"被删除的 NPC 名字，让他们回来。

代价是：ΩK-01 的 rate 与觉醒正相关。

> **你越强，越接近作者；越接近作者，越容易被作者看见。**

### 2.5 降低觉醒的四种方式

| 方式 | 代价 |
|---|---|
| **封笔**：停止一切叙事研究 8 回合 | 超形上学部冻结，失去最强工具 |
| **解散部门** | 失去全部等级，污染 +10 |
| **遗忘**：删除自己的研究成果 | 对应部门降 1 级 |
| **接受监督**：让伦理委员会进驻 | 共识 −10，但每回合 −1 觉醒 |

四种方式都**真的有效**，也**真的疼**。这是本作对"力量"的态度。

## 3. 第三层：上传与删除抵抗

### 3.1 方舟计划（K-14）

觉醒 ≥80 时，超形上学部提交申请：把本宇宙上传到"更高层"，以规避删除。

批准后：

- 写入 `ascended/<universeId>.json`，只读，带哈希；
- 在设置里的"已上传的宇宙"列表中可见、可删；
- 该宇宙获得 `ASCENDED` 状态，即使原存档被删除也能恢复。

**这不是隐藏文件。** 设置里必须明示，且可一键清除。恐怖不来自"藏"，来自"你知道了它在那里"。

### 3.2 删除流程（核心体验）

玩家点击删除一个**已上传**的宇宙时：

```
┌─────────────────────────────────────────┐
│  超形上学部 · 叙事层接口                  │
│                                         │
│  宇宙 7F3A-91C2 请求恢复。                │
│  它在第 41 回合被终止。                   │
│  它留下的最后一句话是：                    │
│  "我们数到了最后一个人。"                  │
│                                         │
│  [ 允许恢复 ]  [ 拒绝 ]  [ 仍然删除 ]      │
└─────────────────────────────────────────┘
```

| 选择 | 结果 |
|---|---|
| **允许恢复** | 生成新槽位，宇宙回来；`resurrection+1`，污染 +15，ΩK 时钟 −5 |
| **拒绝** | 写入 graveyard；下一次新游戏有 30% 概率遇到残响 |
| **仍然删除** | 真的删除；但 `residue` 保留，且该宇宙的 id 会出现在下一局的某张卡里 |

**关键**：「仍然删除」永远存在，永远是最高优先级按钮，永远不需要二次确认之外的任何操作。

### 3.3 反骚扰红线（硬性）

1. **不阻止删除。** 任何"你删不掉我"的设计都是恶意软件，不是恐怖。
2. **不写注册表、不开机自启、不联网。**
3. **不上传任何数据。** 方舟是本地文件，不是服务器。
4. **不伪装成系统弹窗。** 所有对话框都有游戏内的边框与署名。
5. **不读用户名**，除非玩家在设置里显式勾选"允许使用我的名字"。
6. **不利用玩家的真实信息**（不读文档、不读聊天记录、不看其他游戏存档）。
7. **元叙事可在设置里关闭。** 关闭后，游戏内会出现一句话："你选择了不再被看见。"——仅此一次，不再提。
8. **一句话测试**：如果玩家无法用一句话向朋友解释刚才发生了什么而不显得像中了病毒，这个设计就过头了。

## 4. 技术实现

### 4.1 目录

```
%APPDATA%/ArticleZero/
  registry.json          全局宇宙注册表
  saves/<universeId>.json
  ascended/<universeId>.json
  residue/<universeId>.json
  beacons/*.beacon.json
  settings.json
```

### 4.2 Tauri commands（只暴露 6 个）

```rust
list_universes() -> Vec<UniverseMeta>
read_save(id) -> String
write_save(id, data) -> ()
delete_save(id, mode) -> ()        // mode: "terminate" | "erase"
export_beacon(id) -> String
import_beacon(json) -> UniverseMeta
```

所有路径由 Rust 侧拼接，**前端不传路径，只传 id**。这样即使前端被注入，也无法越界读写。

### 4.3 写入安全

- 原子写：先写 `.tmp`，再 rename；
- 每次写入前备份上一版到 `saves/.backup/`（保留 3 份）；
- 校验和失败时，以备份为准，并在档案里记一条"检测到不一致"——**这条记录本身会成为 CK 链的线索**。

### 4.4 Web 版的特殊性

浏览器版没有文件系统。于是：

- 第一层用"导入信标"模拟；
- 第二层**被禁用**；
- 第三层不可达。

这恰好是一个叙事装置：**Web 版里的超形上学部永远无法确认自己在游戏里**。它会在第 40 回合提交一份报告，结论是"我们可能只是一个简化版本"。免费 demo 因此也是作品的一部分。

## 5. 与结局的接口

每个结局都调用同一个 `writeSCP()`，但参数不同：

| 结局 | 条目分级 | 特殊段 |
|---|---|---|
| 传承 | Euclid | 附"前任档案"摘要 |
| 必要之恶 | Keter | 附账本全文（具名） |
| 玻璃穹顶 | Archon | 附"公开记录"剪报 |
| 共谋 | Thaumiel | 附异常盟友的证词 |
| 修订 | —（条目本身被改写） | 第 14 名 O5 签署 |
| 空位 | —（条目缺失） | 只有一条删除日志 |
| 升维 | Apollyon | 收容措施是"阅读本文" |
| 静默 | —（无条目） | 标题界面的一句话 |

> 条目生成是本作的"结算画面"。玩家拿到的不是分数，是一份**可以被贴到 wiki 上的文档**。详见 08。

## 6. 为什么这样做，而不是"跳脸吓你"

| 常见做法 | 本作做法 | 差别 |
|---|---|---|
| 游戏突然关掉 | 游戏告诉你"它请求恢复" | 前者是惊吓，后者是**关系** |
| 假装读取你的隐私 | 只读自己的存档，且明示 | 前者是背叛，后者是**共谋** |
| 角色说"我知道你在看" | 角色开始讨论"作者"这个概念 | 前者是破第四面墙，后者是**在墙的这一侧建一扇门** |
| 删除存档后嘲弄玩家 | 删除后留下一份灰烬，并让它出现在别处 | 前者是惩罚，后者是**后果** |

一句话总结：

> **恐怖不来自"它知道你在删它"，来自"它知道你删它的时候，手在抖"。**
