# 11 · 给上一版实现的一份气话

> 我本来是来查"按钮为什么这么简单"的。查完发现，**按钮只是症状，写它的那套工作方式是病**。
> 这份东西不是要找人背锅，是那套做法必须被按住，否则下一版还是同一个结果。

---

## 一、你们把"层数"当成了"质量"

README 里写着"按钮解剖（8 层）"：投影、外板、上缘高光、内凹面、刻线、图标井、四颗铆钉、状态灯。

数字很好看。问题是——

- 铆钉 `r=1.4`，直径不到 3px；
- 刻线 5 条横线，`stroke-opacity=".03"`；
- 拉丝纹理 `.026`/`.028`；
- 上缘高光宽 1.2px、白 24%。

**这些数字在 1920×1080 下等于不存在。** 你们写的不是 8 层，是 1 层加 7 个不存在。真正落在屏幕上的只有那根 1.1px 的 `stroke`——所以七个按钮、五个图层键、两个预警键、齿轮、印章，**肉眼看起来是同一个东西**。

然后你们给这个状态起了个名字，叫"填充：每块板用 currentColor 低透明度填充，再叠描边和内嵌线，读起来是'实体件'而不是'描边框'"。

它没有读起来像实体件。它读起来像线框图。这句话是写给自己看的，不是看过屏幕之后写的。

---

## 二、v2 到 v11：十次加高、加铆钉、加缺口，一次也没测 1× 可见性

翻一眼变更记录：

- v5：换成 SVG 边框
- v6：数字牌切角
- v7：面板改档案柜
- v8：三条横带非矩形
- v9：底栏改甲板，加 4px 唇线、虚线缆、四颗铆钉
- v10：统一 8 层材质
- v11：动作按钮加高到 44px，印章加高到 52px，上下各五个缺口

**十一版，没有一次是"把它缩到 46px 看看清不清楚"。**

全是加法。加形状、加五金件、加缺口、加高度 4px。你们在调一个自己看不见的东西——因为你们从没在 100% 缩放下看过它，只在 4× 截图里好看。这就像给邮票加第七道防伪线，然后拿放大镜说"质感到位了"。

加铆钉是廉价的。**让 1px 的线在 1× 下站得住，才是设计。** 你们做了十一次便宜的那个。

## 三、自己定的流程，自己第一条就不遵守

`assets/ui/README.md` 白纸黑字：

> 流程是"先画文件，再同步到 `icons.js` 的 sprite"
> 3. 把改动同步到 `assets/icons.js` 的 `frame-*` symbol

**手抄。用眼睛对比两份 SVG，然后手工再写一遍。** 你们还真做了，做了十一版，然后：

| 控件 | 母版 | sprite | 差 |
|---|---|---|---|
| `btn-alert` | 76×26 | 76×28 | 高 2px，形状重画过 |
| `btn-action` | 240×36 | 240×44 | 高 8px |
| `btn-stamp` | 150×46 | 150×52 | 高 6px |

三个对不上。最后一个还是 v11 亲手加高的——**加完改了 sprite，忘了改母版**。

而且这已经是**第三份**手抄副本了：`assets/ui/*.svg`、`assets/icons.js`、`assets/icons.svg`。同一份图形，三个地方，三种状态。文档里还郑重写着"两者内容保持一致"。

不一致。从来就不一致。

## 四、两个按钮，其实是同一个按钮

预警条上「立案」和「处置」：

- 同样的 `frame-abtn`，同样的 76×28；
- 区别只有 `color`：一个 `--muted`，一个 `--accent`。

主按钮和次按钮，形体上没有任何差别。设计文档 §5.2 用一整页讲"提请 vs 下达"的意识形态表达、讲什么时候变灰、讲实心随轴偏移——**到了画面上，主次就是一个字换个颜色。**

更妙的是 `.abtn.primary` 还留着一块 `background: color-mix(…8%…)`，v5 "去掉 CSS 边框"的时候漏了。于是六角按钮背后永远透着一块**矩形**。六边形硬件，方底。十一版没人看出来。

还有那个尖角：`M9 1 h59 l7 11 l-7 11` → 右端尖角在 **y=12**，左端在 **y=14**。一个 28px 高的六角牌，左右尖角差 2px，整块牌是歪的。这行代码从 v10 用到 v12 之前，没人量过。

## 五、素材库不是素材库，是垃圾桶

`assets/scp/` 20 张徽记：

- 18 张 PNG、2 张 SVG，混着；
- 尺寸从 `antimemetics-division.png` 的 100×100 到 `dept.png` 的 2400×2400；
- 实际显示尺寸：**16px / 18px**。

2400px 的图塞进 18px 的框。这不是"高清预留"，这是没想过这件事。

然后同一列树里，「站」「采」「炼」用的是文字徽章（带边框、16px），「逆模因」「超形上」「数学」用的是图片（18px、无边框、`invert + screen`）。**一行里两套表达、两种尺寸、一个有框一个没框。** 你们管这个叫"SCP 识别元素"。

最漂亮的一笔：**12 张图从来没被任何 HTML 引用过，941 KB，占素材总量 48%。**

快一半的仓库是死的。没人删，没人用，也没人知道它们为什么在那儿。大概是"以后也许用得上"——就像那套没人遵守的母版流程。

`assets/README.md` 第三行：

> **当前所有素材均为原创生成，不含任何 SCP 官方图片。**

往下数十四行，同一张表：

**同一页、同一张表、前后矛盾。**

而这份 README 一共 95 行，里面有三处尺寸表过期、一处"由 icons.svg 同步"的假流程、一句自相矛盾的版权声明。

## 七、还有一件事：白主题你们真的打开看过吗

`mockups/01-main-white.png` 就在仓库里。打开它。

米色纸面上，右侧七个按钮是**七个黑窟窿**。地图图层五个、预警条两个、印章一个，全是深色墨块。因为高光写死 `#fff`、投影写死 `#000`，换到浅色底上，深色内凹和黑色投影直接把按钮变成洞。

四套主题、六张对照截图（`01-main-black/white/blue/red.png`、`01-hover.png`、`02-dept.png`）——**六张图都在，问题就在图里，然后被当成"完成"提交了。**

做完不看，等于没做。看完不改，等于更糟：你让人以为这里验证过了。

## 八、公平起见

有几件事做得不坏，别因为这份气话全否了：

- 预警横条的信息密度是对的：一条线读完 K 级、地点、进度、倒计时，还有两个直接动作入口；
- 面板的档案柜处理（切角 + 装订条 + 冲孔）确实比一块圆角矩形有想法；
- 地图那套"点阵 + marching squares 轮廓、共用一份多边形数据"是自己想出来的，轮廓和点阵严丝合缝，这个真不难看；
- 底部甲板的"凹槽 + 台阶 + 缆线"结构感是成立的。

**问题从来不是想象力。是没人把东西放到 100% 缩放下看一眼，然后说"这不行"。**

## 九、所以别再加法了

下一版请守三条，就三条：

1. **先在 1× 下看，再决定加不加。** 任何细节小于 1.5px，等于没画。4× 截图不算验收。
2. **一个形状只能有一份。** 母版改完跑脚本，别手抄。手抄的东西一定会漂，漂了还没人知道。
3. **文档里每句话都要能对着屏幕指出来。** 写"8 层"就要能指出 8 层在 1× 下各自长什么样；写"全部原创"之前先翻一遍 `ATTRIBUTION.md`。

按钮这次不用再"加高 4px"了——加的是**边**：一条 3px 色晕 + 一条上白下黑的渐变描边，46px 下它立刻变成一块金属键。就这么点事，十一版没做到，因为十一版都在加东西，没人想过"厚度"这件事。

**先把看不见的删掉，再加看得见的。**
