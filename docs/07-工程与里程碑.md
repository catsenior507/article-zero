# 07 · 工程与里程碑

## 1. 技术选型

| 层 | 选择 | 理由 |
|---|---|---|
| 前端 | **React 18 + TypeScript + Vite** | 卡牌 UI、文本排版、动画生态最成熟 |
| 状态 | **Zustand + immer** | 单局状态是一棵大树，Zustand 足够且不啰嗦 |
| 样式 | **Tailwind + CSS 变量** | 主题切换（终端绿/纸/暗红）只需换变量 |
| 动画 | **Framer Motion** | 抽卡、翻面、卡面文字变化 |
| 桌面壳 | **Tauri 2** | 体积小；默认不能乱碰文件，符合本作的伦理立场 |
| 内容 | **YAML → 构建期编译 JSON** | 写卡不改代码；Zod 校验 |
| 测试 | **Vitest + Playwright** | 引擎单测 + 关键流程 E2E |
| 打包 | `tauri build` | Win / macOS / Linux |

**为什么不是 Electron**：不是体积问题，是**默认权限**。Tauri 的 fs 权限必须显式声明到目录级，这逼我们把"只碰自己的存档"写进配置，而不是写进自觉。

**为什么不是 Godot**：卡牌 + 大量文本 + 排版，Web 技术快一个数量级。战斗不是重点。

### 关键架构决策：Web 版是"被收容的版本"

```
浏览器版：localStorage，无文件系统 → 第一层（信标）可模拟，第二/三层禁用
桌面版：  完整元叙事
```

这不是妥协，是设定（见 06 文档 4.4）。**免费 demo 因此也是叙事的一部分。**

## 3. 核心数据模型

```ts
interface RunState {
  version: 3;
  universeId: string;          // "7F3A-91C2"
  seed: number;
  turn: number;                // 1..54
  act: 1 | 2 | 3;

  resources: {
    funding: number; staff: number; morale: number;
    capacity: number; assets: number;
    veil: number; contamination: number;
    authority: number; consensus: number;
  };

  axes: { C: number; L: number; K: number; V: number; P: number };

  departments: Record<DeptId, {
    level: number;             // 0..5
    project?: string;          // 进行中的项目 id
    projectTurns?: number;
    loyalty: number;           // 0..100
  }>;

  chains: Record<ChainId, {
    clock: number;             // 100 -> 0
    rate: number;              // 初始 2.2
    stage: 0 | 1 | 2 | 3 | 4;
    filed: boolean;            // 是否立案
    gateFlags: string[];       // 已通过/失败的门槛
  }>;

  deck: {
    drawn: string[];
    discard: string[];
    cooldown: Record<string, number>;
  };

  flags: string[];             // Set 序列化为数组
  ledger: LedgerEntry[];       // 具名代价
  archive: string[];           // 每回合一行，最终变成 SCP 条目

  meta: {
    awakening: number;
    uploaded: boolean;
    resurrection: number;
    deletionSeen: number;
  };
}

interface LedgerEntry {
  turn: number;
  cardId: string;
  optionId: string;
  names: string[];             // 具名的人
  note: string;
}
```

## 4. 确定性随机

单一 seed，按"域"分流，保证读档/回滚可复现：

```ts
const rng = (domain: string, ...keys: (string|number)[]) =>
  mulberry32(hash(seed + domain + keys.join(':')));
```

- 抽卡：`rng('draw', turn)`
- 结算：`rng('resolve', cardId, optionId)`
- 延迟触发：`rng('schedule', cardId, turn)`

**为什么重要**：读档后重复同样的选择必须得到同样的结果，否则"时间异常部的回滚"就变成了纯刷子。玩家要改变结果，只能花资源做"时间线干预"——这正是设计想要的。

> 例外：污染 ≥70 时插入的假卡使用 `rng('corrupt', turn)`，**故意不可复现**。这是"污染"的机制表达。

## 5. 内容管线

```
content/cards/*.yaml
   ↓ build-content.ts
   ├─ Zod 校验（字段、类型、范围）
   ├─ 引用校验（followUp 指向的卡存在；K 链 id 存在）
   ├─ 可达性校验（没有孤立的 key 卡）
   └─ 输出 src/game/content/generated/{cards,chains}.json + types.ts
```

CI 里跑 `pnpm content:check`，失败即阻断。**写错一张卡不应该等到玩到第 40 回合才发现。**

卡牌文本支持占位符 `{{npc}}`，由具名 NPC 系统在运行时填充。

## 6. MVP 范围

第一版能玩的东西，严格限定：

| 项 | 范围 |
|---|---|
| 回合 | 18（第一幕） |
| K 链 | 1 条（XK-17） |
| 部门 | 4 个（站点 / 逆模因 / RAISA / 超形上学） |
| 卡 | 24 张（日常 10 / 流程 8 / 关键 6） |
| 存档 | 单槽位，读/写/删 |
| 结局 | 1 个（传承） |
| 元叙事 | 无 |
| 美术 | 纯排版 + 两台"终端"字体 |

**目标：4–6 周，每周 10 小时。** 做完再决定要不要继续。

### MVP 的验收标准

- 一个没看过设计文档的人，能在 10 分钟内玩完 18 回合；
- 他能说出"我为什么不救那个人"；
- 他会想再开一局；
- 他能感觉到"每个月只能做四件事"的压力。

四条里满足三条才算过。

## 7. 里程碑

| 阶段 | 内容 | 出口标准 | 工期（兼职） |
|---|---|---|---|
| **M0 纸面原型** | 18 张手写卡、18 枚硬币、一张资源表 | 自己玩 3 局，能感到无聊在哪 | 1 周 |
| **M1 可玩循环** | 引擎 + 24 卡 + 4 部门 + 单存档 | 陌生人能玩完 18 回合 | 2–3 周 |
| **M2 垂直切片** | 54 回合 + 3 链 + 10 部门 + 42 卡 | 三种流派都能通关一次 | 4 周 |
| **M3 元叙事层** | 信标、觉醒、方舟、删除抵抗 | 删档测试：三个人里两人"心里一紧" | 3 周 |
| **M4 平衡与打磨** | 蒙特卡洛、可读性、可访问性 | 标准难度存活率 45–60% | 4 周 |
| **M5 发布** | 打包、商店页、隐私说明、条目 | 上线 + 条目过审 | 2 周 |

**总计约 20 周（兼职）。** 如果只有 10 周，砍到 M2 + 简化 M3。

## 8. 风险表

| 风险 | 概率 | 影响 | 对策 |
|---|---|---|---|
| 内容量爆炸（想写 200 张卡） | 高 | 高 | 42 张封顶；先做 18 回合；扩卡留给创意工坊 |
| 平衡难调 | 高 | 中 | `scripts/simulate.ts` 跑 1000 局；监控"必选卡"与"死卡" |
| 元叙事被误认为恶意软件 | 中 | 高 | 商店页明示；只碰自己目录；删除永远可用；开源桌面壳逻辑 |
| 版权问题 | 低 | 中 | 原创异常 + 署名 + 资产 CC BY-SA（见 08） |
| SCP 社区觉得"蹭" | 中 | 中 | 先做好游戏，再写条目；条目必须独立成立 |
| 卡牌文本量大、风格不统一 | 高 | 中 | 模板 + 风格指南 + 每张卡过"去掉数值还像不像基金会"的测试 |
| 元叙事让玩家不适 | 中 | 中 | 设置可关闭；红线 8 条（06 文档） |

## 9. 平衡验证

### 蒙特卡洛

```bash
pnpm simulate --runs 1000 --difficulty standard --policy greedy
```

输出：

- 存活率（目标 45–60%）；
- 每条 K 链的阻止率（目标：正确立案后 ≥75%）；
- 单卡选择率分布（>80% 为必选卡，<10% 为死卡）；
- 平均账本人数（目标 3–8，超过 12 说明冷酷路线过强）。

### 人工测试

每轮找 3 个人：

1. 一个 SCP 爱好者（看设定是否成立）；
2. 一个策略游戏玩家（看深度）；
3. 一个没听过 SCP 的人（看门槛）。

三个人都要能说出"我在第几回合做错了什么"。
