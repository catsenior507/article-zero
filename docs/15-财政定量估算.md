### 3.2 设施 · $33.7M（设计稿 28.2）

| 项 | 计算 | 年成本 |
|---|---|---|
| 建设（沉没，不进月度） | 19 × 150,000 sqft × $960 × 1.5 | **$4.1B 一次性** |
| 维护（造价的 6.5%） | $4.1B × 0.065 | $266M |

| 水 / 安保系统 / 消耗品 | 19 × $0.11M/月 | $25M |
| 合计 | | **$404M / 年 ≈ $33.7M / 月** |

设计稿写 $28.2M，这里算出 $33.7M——差 19%。把维护降到 5%、或把平均功率降到 6MW，就落回 28M 附近。**结论：设计值偏乐观，但在同一量级。**

> 注意最上面那行：19 个站点的一次性建设成本约 **$4.1B**。这解释了为什么"新建站点"不能是 $30M——见 §6。

## 6. 被现实打脸的三处

### 6.1 新建站点 $30M 太便宜（最严重）

150,000 sqft × $960/sqft = **$144M**，加秘密溢价 1.5× = **$216M**。设计稿的 $30M 算上溢价只有现实成本的 **1/7**（不含溢价约 1/5）。

建议改法（三选一）：

- 新建站点一次性 **$120M**（不含溢价），分 3 个月支付；
- 或保持 $30M，但定义为"一个前哨/租用站点"，真正的收容设施另有价格；
- 或把"容量 +2"改成"改造现有站点"，价格 $40M。

### 6.2 1 编制点 = 30 人必须写死

如果按 50 人/点（4,200 人），人事变 $28.7M，月支出 $101M，开局赤字 −$15M，游戏难度完全变了。
**这条假设要进存档，不能只活在文档里。**

### 6.3 出动 $4M 里只有 $0.8M 是军事成本

不是错，但要意识到：玩家每次点"处置"，付的其实是**善后费**。这正好呼应主题——钱花在"不让别人知道"上。

## 7. 敏感性

| 变量 | 取值 | 人事/月 | 设施/月 | 月支出 | 净额 |
|---|---|---|---|---|---|
| 每点人数 | 30 | 17.2 | 28.6 | 90.2 | +17.7 |
| | 50 | 28.7 | 28.6 | 101.7 | +6.2 |
| | 100 | 57.4 | 28.6 | 130.4 | −22.5 |
| 站点规模 | 80k sqft | 17.2 | 15.3 | 76.9 | +31.0 |
| | 150k sqft | 17.2 | 28.6 | 90.2 | +17.7 |
| | 300k sqft | 17.2 | 57.3 | 118.9 | −11.0 |
| 秘密溢价 | 1.0× | 17.2 | 22.7 | 84.3 | +1.8 |
| | 1.5× | 17.2 | 28.4 | 90.0 | −3.9 |
| | 2.0× | 17.2 | 34.1 | 95.7 | −9.6 |

读法：**人数是最敏感的旋钮**，站点规模次之。调难度优先动这两个，不要动单价。

## 8. 建议

1. 把 §2 的三条假设写进 `mockups/save.js` 的 `world` 字段（`headcountPerPoint`、`siteSqft`、`secrecyPremium`）；
2. 新建站点价格从 $30M 改为 **$120M 或分三期**；
3. 设施维护系数定 **5%**，与设计稿的 28.2 对齐；
4. 每季度按现实物价重算一次这张表（CPI 或能源价格变动超过 10% 时）。
